# PS02 测试数据 与 PIS 生产信息化系统 数据对接分析

> 依据：`http://pis.const.cc/#/testing`（生产信息化系统-测试管理模块，后端 API `http://192.168.4.104:9491/api/Testing/*`）
> 全部字段经实际调用接口采集（2026-08-14），非推测。

---

## 一、总体说明

### 1.1 系统现状

| 项 | 说明 |
|---|---|
| PIS 系统 | 生产信息化系统（Vue SPA），`#/testing` = 测试管理模块，按**批次**维度统计通过率/耗时/故障/重测，可下钻到单台设备、单个测试项 |
| PIS 后端 | `http://192.168.4.104:9491`，接口前缀 `api/Testing/*` |
| PIS 数据源 | **独立数据库**（非 `192.168.4.103` 的 `cst_auto_test_data`）——经实测该库仅有 `pcba_test_data`/`ps02_test_data` 等 4 张自建表，无 PIS 表 |
| PS02 上报库 | `192.168.4.103:3306/cst_auto_test_data`（`ps02_test_data` + `ps02_test_data_details`） |
| 数据流 | **两系统目前数据不互通**。PS02 数据要进入 PIS testing 页面，需另行对接（共享库 / API 上报 / Excel 导入，PIS 已有 `ImportTestData` 导入通道） |

### 1.2 文档目的

让 `ps02_test_data` / `ps02_test_data_details` 保存的字段**覆盖 PIS testing 页面所需全部信息**，为后续对接（上报/导入）铺路。本文先梳理 PIS 字段定义与计算口径，再给出本项目的字段缺口与新增建议。

## 三、计算口径

> 以下口径由实测数据反推验证（810A26014 / 660TL26005 / 660TLCT26008 三批次）：

| 指标 | 计算公式 | 验证 |
|---|---|---|
| 一次通过率 `FirstPassRate` | `FirstPassQty / TestQty × 100` | 660TL26005：7/8=87.5 ✓；660TLCT26008：7/13=53.85 ✓ |
| 通过率 `PassRate` | `PassQty / TestQty × 100` | 660TL26005：8/8=100 ✓；660TLCT26008：8/13=61.54 ✓ |
| 测试项通过率 `ItemPassRate` | 该测试项**通过次数 / 执行总次数 × 100** | "加热功能测试"=32.26%（失败 21 次） |
| 测试项失败次数 `FailCount` | 该测试项失败执行次数 | — |
| 单台耗时 `Duration` | 该设备 `EndTime - BeginTime` | — |
| 测试项耗时 `Duration(项)` | `EndTime - StartTime`（秒） | 810A26014：0.07s |
| 批次平均耗时 `BatchAvgDuration` | `Σ(各台 BeginTime→EndTime) / TestQty`（含并发等待） | — |
| 测试项耗时总和 `SubItemTotalDuration` | `Σ(该台各测试项 Duration)` | — |
| 是否一次通过 `IsFirstPass` | 设备整测**首轮全部测试项通过**（重测后过不算一次通过） | — |
| 耗时阈值 `Threshold` | PIS 按历史 `Q1/Q3` 分位数动态计算；`IsOverThreshold = AvgDuration > Threshold` | — |

**一次通过 vs 最终通过（关键口径）**：
- `FirstPassQty`/`IsFirstPass`：**首轮测试即全部通过**，中途重测过的设备不算
- `PassQty`/`IsPass`：**最终**通过（允许重测后通过）

## 五、需要新增的字段

### 5.1 主表 `ps02_test_data` 新增

| 新增字段 | 类型 | 对应 PIS | 理由（必须性） |
|---|---|---|---|
| `product_family` | varchar(64) | ProductFamily | PIS 按产品族分组/筛选；现有 `device_model` 无此维度，**无法推导**（需产品档案映射） |
| `product_name` | varchar(128) | ProductName | PIS 批次列表展示产品名；**无法推导** |
| `device_type` | varchar(64) | DeviceType/DeviceCode | PIS 设备型号码（如 `PS02A`）；现有 `device_model` 语义是型号名，建议对齐统一 |
| `test_type` | int | TestType | PIS 测试类型（1=整机测试 2=功能自检）；现有 `type`(0/1) 需**映射对齐**（PIS 用 1/2） |
| `pass_qty` | int | PassQty | 批次统计直接展示；主表按 SN 唯一，聚合需跨行扫描，冗余有利 |
| `fail_qty` | int | FailQty | 同上 |
| `first_pass_qty` | int | FirstPassQty | 同上，一次通过口径需单独统计 |
| `first_pass_rate` | decimal(5,2) | FirstPassRate | 计算值（`first_pass_qty/test_qty×100`），冗余避免 PIS 重复聚合 |
| `pass_rate` | decimal(5,2) | PassRate | 计算值（`pass_qty/test_qty×100`） |
| `tested_device_count` | int | TestedDeviceCount | 批次已测设备数（可能小于 batch_count，含重测去重） |
| `batch_count` | int | BatchCount | 批次应测设备总数（扫码数） |
| `avg_duration` | decimal(10,2) | AvgDuration | 单台平均耗时（秒），PIS 耗时分析核心 |
| `batch_avg_duration` | decimal(10,2) | BatchAvgDuration | 批次平均耗时（秒） |

> 说明：`TestQty` 可由 `tested_device_count` 充当；`FirstPassRate/PassRate/耗时` 均可在保存时由引擎计算后写入（冗余），避免 PIS 端聚合依赖不完整明细。

### 5.2 子表 `ps02_test_data_details` 新增

| 新增字段 | 类型 | 对应 PIS | 理由（必须性） |
|---|---|---|---|
| `duration` | decimal(10,2) | Duration | PIS 测试项耗时分析核心；虽可由 `end_time-start_time` 推导，但**重试/中断场景下起止时间不能精确反映实际耗时**，需单独记录 |
| `measured_value` | varchar(255) | （原始数据/故障） | 测试项**实际测量值**（PIS 原始数据与故障分析的关键）；当前 `TestProcessData` 是曲线序列，非最终测量值文本，**无法推导** |
| `threshold` | decimal(12,4) | Threshold | 该测试项判定阈值（上限/下限），故障分析展示依据 |
| `is_over_threshold` | bool | IsOverThreshold | 是否超阈值（耗时维度） |
| `fail_reason` | varchar(500) | FaultDesc | 失败原因描述；现有 `error_message` 为单行，PIS `FaultDesc` 为**多行结构化**（如 `30004_加热板未到位_`），需按 PIS 格式拼接 |
| `retry_index` | int? | RetryIndex | 重试序号（null=未重试）；PIS 重测维度**必须** |
| `retry_category` | varchar(32) | RetryCategoryName | 重测类别名（如"重测"）；PIS 重测统计维度 |
| `is_retest` | bool | — | 是否重测执行（本地快速过滤用） |

### 5.3 设备级字段（主表，PIS 设备明细）

| 新增字段 | 类型 | 对应 PIS | 理由 |
|---|---|---|---|
| `first_pass` | bool | IsFirstPass | 设备**首轮整测全部通过**（区别于最终 `is_pass`）；引擎可判定（任一项首轮 Fail 即 false） |
| `first_time` / `last_time` | datetime | FirstTime / LastTime | 首末次测试时间（当前只有 start/end 单次；重测场景需区分） |

## 六、对接建议

1. **先确认对接方式**（PIS 已开放 `ImportTestData` Excel 导入；也可共享库或 API 上报）——决定字段命名最终对齐与是否需冗余统计字段。
2. **批次号规范**：PIS 批次号含型号+日期+流水（如 `810A26014`），建议 PS02 生成规则与其对齐，避免 PIS 侧识别失败。
3. **测试类型映射**：现有 `type`(0=整机 1=自检) → PIS `TestType`(1/2)，建议保存时直接写 PIS 口径（1/2），或保留映射表。
4. **产品信息映射**：`device_model` → `product_family`/`product_name`/`device_type` 需要产品档案字典（型号→族/名），建议在项目配置中维护。
5. **故障描述格式**：PIS `FaultDesc` 为多行 `错误码_描述_` 结构，`fail_reason` 建议按此格式拼接（复用现有 `ErrorMessage` 来源）。
6. **重测标识**：引擎已支持 `RetryOnFail` 重试，保存时同步写 `retry_index`/`retry_category`/`is_retest`，即可支撑 PIS 重测分析。
